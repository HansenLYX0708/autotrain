# 无监督异常检测框架接入方案（TorchAnomaly）

状态：**待 review**，尚未写任何实现代码。
适用场景：slider 外观检测 —— 正常样本充足，缺陷样本充足但**只用于验证、不进训练**，缺陷尺度大小都有，验收需要**像素级指标**。

---

## 1. 结论

| 项 | 决定 |
|---|---|
| 算法 backend | **anomalib**（Intel，Apache-2.0），**钉定版本** |
| 接入方式 | 在 `torchtrain/` 内新增 `ad/` 子包 + `--task ad`，**薄适配层**调用 anomalib 的 `Engine` API（不调它的 CLI） |
| 新框架名 | `TorchAnomaly`，`family: 'torch'`，新增 `taskKind: 'anomaly'` |
| python 环境 | 独立 venv，通过 `frameworkPythonMappings["TorchAnomaly"]` 指定，**不与现有 torch 环境共用** |
| 首批算法 | PatchCore（基线）、STFPM（轻量+可 tiling）、EfficientAD（产线候选）、SuperSimpleNet（半监督预留） |
| 训练计数单位 | `stepUnit: 'iter'` |
| checkpoint | `<save_dir>/best_model/model.ckpt`（沿用 `checkpointLayout: 'nested'`） |

选 anomalib 而不是自研的核心理由：**它的配置文件顶层就是 `model:` / `data:` / `trainer:` 三个互不重叠的块**，与本平台"数据集/训练/模型三份 YAML 深合并"的结构天然 1:1 对应，且 AUROC/F1、自适应阈值、分数归一化、热力图可视化、ONNX/OpenVINO 导出全部现成。
选薄适配层而不是直接调 `anomalib train` CLI 的理由：平台的进度条、loss 曲线、best checkpoint 全靠解析 stdout 文本，而 anomalib CLI 输出的是 rich 进度条，无法解析；同时它的产出目录结构与平台约定冲突（见 §2 第 3 条）。

## 2. 事实核查（已读 anomalib `main` 源码确认，非文档转述）

这几条直接决定了适配层必须做什么，其中 2 条与官方文档不一致：

1. **配置形状**：`model:` / `data:` / `trainer:`，每块 `class_path` + `init_args`。
   来源：`examples/configs/model/patchcore.yaml`、`efficient_ad.yaml`。
2. **`Engine.from_config(config_path) -> (engine, model, datamodule)`** 存在，内部走 `AnomalibCLI(args=["fit","--config",path], run=False)`。这是适配层最省事的接入点：把合并后的 YAML 交给它，拿回三个对象，再自己控制训练循环外围。
   来源：`src/anomalib/engine/engine.py:916`。
3. **`engine.fit()` 会强制建版本化目录**：`_setup_workspace(versioned_dir=True)` 把 `default_root_dir` 改写成 `<root>/<ModelName>/<dataset_name>/<category>/vN`。
   → **平台约定的 `<save_dir>/best_model/model.ckpt` 不会自动出现**，适配层必须在训练结束时把 `engine.best_model_path` 复制过去。
   来源：`engine.py:296-298, 407-413`。
4. **默认 `Evaluator` 只注册 `test_metrics`，`val_metrics` 为空**（`image_AUROC` / `image_F1Score` / `pixel_AUROC(strict=False)` / `pixel_F1Score(strict=False)`）。
   → 训练过程中的 validation **不产生任何指标**，监控页曲线会是空的。适配层必须显式构造带 `val_metrics` 的 `Evaluator` 注入模型。
   来源：`src/anomalib/models/components/base/anomalib_module.py:366-385`。
5. **`Engine` 没有 `image_metrics` / `pixel_metrics` 参数**（只有 `callbacks` / `logger` / `default_root_dir` / `**trainer_kwargs`）。官方 tiling 教程里那段 `Engine(image_metrics=[...])` 已经过期，照抄会报错。
   来源：`engine.py:157-176`。
6. **`image_size` 不在 datamodule 上，在模型的 `pre_processor` 里**：`Model.configure_pre_processor(image_size, center_crop_size)`。`Folder` 的构造参数里既没有 `task` 也没有 `image_size`。
   来源：`anomalib_module.py:311-336`、`src/anomalib/data/datamodules/image/folder.py:113-140`。
7. **tiling 只有 4 个模型支持**：PaDiM / PatchCore / ReverseDistillation / STFPM，经 `trainer.callbacks` 传 `TilerConfigurationCallback(enable, tile_size, stride, remove_border_count, mode)`。**EfficientAD 不支持**。
   来源：`src/anomalib/callbacks/tiler_configuration.py`、官方 tiling 教程。
8. **PatchCore 没有 loss**：`training_step` 返回常量 0.0，`configure_optimizers()` 返回 `None`。STFPM / EfficientAD / RD 有真实 loss。
   来源：`src/anomalib/models/image/patchcore/lightning_model.py`。
9. 依赖与许可：Apache-2.0，`python>=3.10`，`lightning>=2.6`，torch 2.6+，另有 jsonargparse(<4.47)、kornia、freia、omegaconf、opencv-python-headless、imagecodecs 等。

## 3. 数据集约定

### 3.1 磁盘布局（新格式 `AnomalyFolder`）

```
<userDatabasePath>/<user>/datasets/AnomalyFolder/<name>/data/
  train_good/       正常图 —— 唯一进入训练的目录
  test_good/        正常图（测试用，可选；不给则从 train_good 按比例切）
  test_ng/          缺陷图 —— 只进 val/test，不参与训练
  test_ng_mask/     缺陷掩膜 PNG，与 test_ng 同名（像素级指标必需）
```

对应 `Folder` 的 `normal_dir` / `normal_test_dir` / `abnormal_dir` / `mask_dir`。

### 3.2 数据泄漏必须写进 UI 提示

`Folder` 的默认切分是 `test_split_mode=from_dir`、`val_split_mode=from_test`、`val_split_ratio=0.5`：**test 集会被对半切出一份 val，而 val 正是 anomalib 用来搜自适应阈值和做分数归一化的集合。**
也就是说"报告出来的 F1"是在**参与过阈值选择的数据**上算的。方案要求：

- 数据集导入时把 NG 图**显式**分成 `val` 与 `holdout` 两份（或提供 `val_split_ratio` 输入框并在界面上说明其含义）；
- 验收数字以 holdout 上的 `tools/val.py` 结果为准，训练日志里的 val 指标只作为趋势参考。

这一条是整个方案里最容易出错、也最影响"这模型到底行不行"结论的地方。

### 3.3 掩膜标注

复用现有 napari 标注器（`tools/napari_seg/annotate.py`）以二类模式标 NG 图，导出的 `Annotations/*.png` 直接作为 `test_ng_mask`。需确认一点：anomalib 的 `FolderDataset` 把掩膜按文件名 stem 匹配还是按排序位置匹配 —— **实施前实测**，若是按排序则导入时必须保证两目录文件名一致。

## 4. 三份 YAML 的形状

深合并顺序不变：dataset → training → model（后者覆盖前者，map 递归合并，**序列整体替换**，见 `src/lib/yaml-merge.ts`）。

### 4.1 数据集配置（负责"数据从哪来"）

```yaml
# Dataset configuration for slider_v1
# Generated by AutoTrain Platform (AnomalyFolder)
data:
  class_path: anomalib.data.Folder
  init_args:
    name: slider_v1
    root: D:/data/user/datasets/AnomalyFolder/slider_v1/data
    normal_dir: train_good
    normal_test_dir: test_good
    abnormal_dir: test_ng
    mask_dir: test_ng_mask
    extensions: ['.png', '.bmp', '.jpg']
    train_batch_size: 8
    eval_batch_size: 4
    num_workers: 4
    test_split_mode: from_dir
    val_split_mode: from_test
    val_split_ratio: 0.5
    seed: 42
```

### 4.2 训练配置（负责"怎么练"）

```yaml
trainer:
  max_epochs: 100
  max_steps: -1
  check_val_every_n_epoch: 1
  accelerator: gpu
  devices: 1
  precision: 32-true
  enable_progress_bar: false          # 必须：否则 rich 进度条污染 stdout
  callbacks:                          # 序列整体替换，所以 tiling 只能由本文件定义
    - class_path: anomalib.callbacks.tiler_configuration.TilerConfigurationCallback
      init_args:
        enable: true
        tile_size: [512, 512]
        stride: 256
data:
  init_args:                          # 深合并叠加到数据集配置上
    train_batch_size: 8
    num_workers: 4
autotrain:                            # 平台私有块，适配层读取后剥离
  log_iter: 20
  best_metric: image_AUROC
```

### 4.3 模型配置（负责"练什么"）

```yaml
model:
  class_path: anomalib.models.Patchcore
  init_args:
    backbone: wide_resnet50_2
    layers: [layer2, layer3]
    pre_trained: true
    coreset_sampling_ratio: 0.1
    num_neighbors: 9
autotrain:
  image_size: [512, 512]              # 交给 Model.configure_pre_processor()
  center_crop_size: null
```

### 4.4 `autotrain:` 私有块的作用

`image_size` 若按 anomalib 原生写法要嵌一整个 `torchvision.transforms.v2.Compose` 的 `class_path`，在 jsonargparse 里既啰嗦又易错。方案改为：平台只写 `autotrain.image_size`，适配层调用 `Model.configure_pre_processor(image_size=...)` 生成 `PreProcessor` 注入，然后把 `autotrain:` 块从传给 `Engine.from_config` 的临时配置里删掉。

代价：合并后的 job config 不是"纯 anomalib 配置"，不能直接喂 `anomalib train`。这是有意的取舍 —— 换来的是模型配置表单里 `image_size` 就是一个普通数字输入框。

## 5. 适配层

### 5.1 目录

```
torchtrain/
  torchtrain/
    ad/
      __init__.py
      config.py      拆 autotrain: 块、写临时纯 anomalib 配置
      logger.py      Lightning callback → Paddle 风格 stdout 行
      evaluator.py   构造带 val_metrics 的 Evaluator（补第 4 条坑）
      runner.py      train / val / predict / export 四个入口的公共实现
  tools/train.py val.py predict.py export.py    统一加 --task ad 分支
```

放在 `torchtrain/` 内而不是新建仓库：这样 `pathField` 仍是 `torchPath`，**不需要给 `SystemConfig` 加列、不需要改 Settings 页的框架路径卡片**。anomalib 只在 `ad/` 分支里 import（懒加载），所以现有 torch 环境没装 anomalib 也不影响 TorchSeg/TorchDet。

### 5.2 `tools/train.py --task ad` 流程

```
1. 解析 CLI（沿用现有 cli.py）：--config --save_dir --do_eval --amp --use_vdl
2. 读合并 YAML，切出 autotrain: 块
3. 写临时纯 anomalib 配置到 <save_dir>/.anomalib_config.yaml
4. engine, model, datamodule = Engine.from_config(临时配置)
5. model.pre_processor = type(model).configure_pre_processor(image_size=autotrain.image_size)
   model.evaluator     = 带 val_metrics 的 Evaluator（image/pixel AUROC + F1）
6. engine.trainer 追加两个 callback：
     - LogCallback  → 打印 [TRAIN] / [EVAL] 行
     - ModelCheckpoint(monitor=autotrain.best_metric, mode=max)
7. engine.fit(model=model, datamodule=datamodule)
8. copy(engine.best_model_path → <save_dir>/best_model/model.ckpt)
9. engine.test(...) → 打印最终 [EVAL] 行 + 写 <save_dir>/best_model/metrics.json
```

### 5.3 命令行兼容性

`buildTrainCommand` 对 `cliStyle: 'config-flags'` 生成的是
`python tools/train.py --config <cfg> --do_eval --save_dir <dir> [--amp] [--use_vdl]`
（见 <ref_snippet file="D:\_work\projects\autoTraining\Autotrain_g\src\lib\job-commands.ts" lines="53-72" />）。
`ad` 分支必须接受全部这些 flag：`--amp` → `trainer.precision=16-mixed`；`--use_vdl` → 加 `TensorBoardLogger`；`--do_eval` → 是否在 fit 后跑 test。

## 6. 日志行格式

沿用 PaddleSeg 的行形状，使现有解析逻辑可最大程度复用。

**TRAIN**（格式与 PaddleSeg 完全一致，可直接复用现有正则）：

```
[2026/08/19 10:21:03] INFO: [TRAIN] epoch: 3, iter: 600/8000, loss: 0.1837, lr: 0.000100, batch_cost: 0.0921, reader_cost: 0.0113, ips: 86.8 samples/sec | ETA 00:11:22
```

- PatchCore 无 loss：`loss: 0.0000` 恒定，但 `iter` 仍按"记忆库填充进度 = batch_idx / 总 batch 数"递增，保证进度条会动。

**EVAL**（新格式，需要新解析分支）：

```
[2026/08/19 10:22:31] INFO: [EVAL] #Images: 40 image_auroc: 0.9812 image_f1: 0.9231 pixel_auroc: 0.9633 pixel_f1: 0.5412 threshold: 12.3456
[2026/08/19 10:22:31] INFO: [EVAL] The model with the best validation image_auroc (0.9812) was saved at iter 3000.
```

第二行刻意与 PaddleSeg 的 best 行同形，`bestIter` / `bestMetric` 的抽取可以共用。
**解析器实现要求**：不要硬编码指标名清单 —— 从 `trainer.callback_metrics` 拿到什么就打印什么，已知的四个键落列，未知键塞 `classMetrics` JSON。这样 anomalib 换指标名不会让解析器静默丢数据。

## 10. 未决问题与风险

1. **两种缺陷尺度要不要两个模型。** tiling 只覆盖 PaDiM/PatchCore/RD/STFPM，EfficientAD 用不了。若细小缺陷必须 tiling、而大面积异常又需要全局视野，最可能的结论是**跑两个 job 各管一段**（细小 → PatchCore+tiling，大尺度 → EfficientAD 全图），推理端做或运算。阶段 0 要专门验证这一点。
2. **anomalib 版本策略。** 每个小版本都在删已弃用 API（2.6 就删了一批）。方案要求 `requirements-ad.txt` 里写死 `anomalib==2.6.x`，升级作为独立任务处理，不随手 `pip install -U`。
3. **PatchCore 内存。** 记忆库大小随分辨率×tile 数×训练图数增长，高分辨率+大量正常图可能吃满显存/内存。`coreset_sampling_ratio` 是主要旋钮，阶段 0 记录实测占用。
4. **图像位深/通道。** 16-bit 或灰度图能否被 anomalib 直读需实测；不行就在导入时统一转 8-bit 3 通道 PNG（现有链路已有 TIFF→PNG 暂存可参考）。
5. **掩膜匹配规则**（§3.3）需实测。
6. **阈值与数据泄漏**（§3.2）—— 需要产品上明确"哪批 NG 图用于定阈值、哪批用于报数"。
