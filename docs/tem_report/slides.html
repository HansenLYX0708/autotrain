01 · 接口

接口约定：只吃标签图，不吃混合预览

这是整条链路唯一的耦合点，所以工具主动做了防呆。

为什么必须拒绝混合预览 它的颜色被灰度图污染了，不是标签图。如果硬算，每个类别的边界都会错， 而且错得很"合理"——不会崩，只会安静地给出一整页错数字。

工具的做法：把 RGB 往标准调色板上吸附，统计离色像素比例，超过 5% 就直接报错。

P / L 模式  → 索引即类别 id，直接读
RGB 模式    → 吸附到调色板，离色 >5% 报错
其它模式    → 不支持
调色板为什么能反查 build_palette() = PASCAL VOC colormap 去掉首个黑色项，所以 类别 id == 调色板索引。 标注工具和量测工具共用同一个函数，两边不可能走偏。

02 · 分割训练

② 一个训练任务 = 三份 YAML 深合并

网页端不让人写整份配置，而是拆成三份独立维护、启动时合并。

数据集配置 ─┐
训练配置   ─┼─►  深合并 YAML  ─►  训练入口脚本  ─►  stdout 解析进 TrainingLog 表
模型配置   ─┘

优先级：dataset → training → model（后者覆盖前者，逐 key 合并）
配置负责典型内容
数据集数据从哪来train_dataset / val_dataset / dataset_root / num_classes / transforms
训练怎么练batch_size / iters / optimizer / lr_scheduler
模型练什么model（架构 + backbone）/ loss
为什么必须"深合并"而不是拼文本 拼接会产生重复的顶层 key。解析器容忍（后者赢），但文档本身是非法 YAML， 再用 yaml.parse() 读就抛 Map keys must be unique。
而且合并是逐 key 的：训练配置可以只改 train_dataset.transforms 里的一项， 不用把整个数据集块重抄一遍。
好处任意训练预设 × 任意模型预设 × 任意数据集，都能自由组合， 不需要为每种组合维护一份完整配置。
02 · 分割训练

③ 分割训练的三个硬约束

全部是踩过的坑，每一条都会让训练直接失败，或让配置静默不生效。

1 · 按 iteration 训练，不是 epoch iters 才是总步数，warmup_iters、save_interval 同理。 数据库里那几个 epoch 命名的列，对分割项目存的其实是迭代数。
2 · len(loss.types) 必须等于模型输出的 logits 数 主头 + 辅助头。不匹配就是 RuntimeError: The length of logits_list should equal to the types of loss config。
所以 loss: 永远写在模型配置里，绝不写在训练配置里 —— 这样任意训练预设都能和任意模型预设自由组合而不会配错。
架构logits架构logits
UNet1PP-LiteSeg (STDC1/2)3
DeepLabV3+1BiSeNetV25
OCRNet2——
3 · save_dir / save_interval / log_iters 是命令行参数，不是 YAML 键 写进 YAML 不会报错，但不生效 —— 这是最容易被忽略的一条。

03 · 量测工具

所有数字的两个前提：标尺 & 校平

标尺（nm/px）　默认从文件名正则取视场： ..._FOV_76.37nm.png → 76.37 nm，再除以图像实际宽度。 样本批次 26 张全部解析成功：76.37 / 1024 = 0.074580 nm/px。

  • 除以实际宽度而非写死 1024 —— 掩膜以别的尺寸导出时仍然正确，宽度≠1024 会 warning
  • fov_nm / image_width_px / scale_nm_per_px / scale_source 全部记进 JSON 和 CSV
  • 解析不到且没给 --scale-nm 时直接报错，不会静默用错标尺

校平（rectification）　Leveling 层拟合直线得倾角，整图旋转到水平后再量。 "dy 是向下偏了多少"这句话，只有校平之后才有物理意义。

  • 插值必须最近邻：数组装的是类别 id，任何平均都会造出没预测过的类
  • 填充值用 255(ignore) 而非 0(背景) —— "画幅之外"与"预测为背景"因此可区分，M5 排除切边全靠它
  • 每个点同时给校平坐标和原图坐标，可直接叠回原始 TEM 图
  • 代价：重采样噪声 1–2 px。自检残余角 0.007°，但 dy 误差可达 ~5 px；--no-rotate 可完全避开

04 · 量测 M1

leveling — 整图校平基准

唯一一个"结果会反过来影响其它所有量测"的模块。

定义Leveling 类 → 最大连通域 → Guo–Hall 骨架 → 直线拟合 → 倾角
角度用 TLS（总体最小二乘）。OLS 在残差与 x 跨度可比时会系统性压平斜率，TLS 对方向无偏
R²/rmse用 OLS y~x，因为"fit R²"通常就是这个意思。两者都输出，差异摆在明面上
可靠性angle_stderr_deg（斜率标准误），不看 R²
自检校平后重新拟合，残余角 > 0.05° 告警
实测26 张倾角中位数 0.259°，范围 −2.263°～+1.002°（上样倾斜在 ±2° 内）
R² 对近水平的层没有意义 R² = 1 − SS_res/SS_tot，而水平层的 SS_tot（y 的方差）本身极小 —— 一条 1029 px 长、rmse 仅 1.9 px 的优秀直线，也只能得到 R² ≈ 0.02。
Leveling / MgO_C / Non_mag 都是这种情况。结果里带 fit_r2_degenerate: true 和 fit_r2_note 说明。
判断平直度请看 rmse 与 max_residual。
校平后的重新拟合是免费的自检 如果旋转矩阵、逆变换、坐标映射任何一环写错，残余角就不会接近 0。 这条检查每张图都会跑，成本几乎为零。
04 · 量测 M2

mgo_c — MgO_C 平直度与倾角

定义MgO_C 骨架 → TLS 直线
b3 / b4把骨架 x 最小/最大的极值点投影到拟合直线上得到的线段端点
输出角度、fit_r2(+退化标记)、fit_slope/intercept、rmse、max_residual、perp_rmse、b3/b4、fit_length、residual_profile
实测rmse ≈ 0.045 nm (0.6 px)，max_residual ≈ 0.126 nm；倾角批次内 −3.5°～+3.5°
为什么要 b3/b4，而不是只用 b1/b2 b1/b2 是骨架的真实端点，b3/b4 是直线模型上的端点。 两者之差 = 该处层的局部起伏。
所以 a1→b1 和 a1→b3 同时给出：前者对准真实端点，后者对准模型、对局部毛刺不敏感。
实测两者 dx 几乎一致（中位数 5.332 / 5.333 nm，差 0.001 nm），但 b3 的 dy 离散度更小。
04 · 量测 M3

interfaces — 层间端点偏差（核心指标）

端点定义a1 = SAF_Ru_L 骨架 x 最大端 · a2 = SAF_Ru_R 骨架 x 最小端
b1/b2 = MgO_C 骨架 x 最小/最大端 · b3/b4 = MgO_C 拟合线段端点
四组偏移a1_b1 · a1_b3 · a2_b2 · a2_b4，各含 dx/dy/distance（px + nm）
符号约定dx>0 = b 在 a 右侧；dy>0 = b 比 a 更低。这句话原样写在每个 offset 的 convention 字段里
实测a1_b1.dx 中位数 +5.332 nm (σ 0.61)，a2_b2.dx −5.332 nm (σ 0.50) —— 左右严格对称
骨架端点会内缩 Guo–Hall（任何形态学细化都一样）会从区域尖端回缩约半个带宽。合成算例：13 px 厚的层正好内缩 6 px。
--endpoint-extend region 可沿切线外推补偿（该模式下自检 a1 误差为 0），默认关闭以忠实于 Guo–Hall。
好消息：dx/dy 是两端点之差，两侧内缩量相近时大部分抵消。
04 · 量测 M4

*_dip — 端点 5 nm 内的最大下沉量

从 a1（或 a2）沿骨架回走 5 nm，这段里层最多往下掉了多少。表征端点附近的塌陷。

基准端点自身：dev = y − y(端点)，正值 = 更低
窗口沿弧长回走，不是沿 x
输出window · window_polyline · max_downward_deviation · max_downward_point · max_downward_arclength · max_abs_deviation · deviation_profile
实测左 0.597 nm（0～1.417），右 0.709 nm（0.224～1.268）
为什么按弧长而不按 x 端点附近层是弯的。按 x 取窗口，会在不同图上覆盖到不同长度的实际层，量出来的数就不可比了。
为什么把整条 deviation_profile 也写进 JSON 想换个窗口长度、或想确认"最大值是不是一个孤立毛刺"，不必重跑整批，直接在 JSON 上复核。
M5 的 curvature_profile、M2 的 residual_profile 同理 —— 这是贯穿整个工具的一条设计原则。
叠加图画法（洋红色） 加粗骨架段 = 被搜索范围 · 两端竖线 = 窗口边界 · 虚线 = 端点基准线 · 箭头指向最大偏差点并标出数值。不必开 JSON 就能读出这个数。
04 · 量测 M5 (1/2)

milling_l/r — 取哪一侧？

一条 Milling 带有两个侧面：一侧贴器件，一侧朝真空。要量的是离子研磨真正加工出来的那面。

采用：邻接判据 默认 outer = 保留"不与任何其它类相邻"的边界像素，再取轮廓顺序上最长连续段。与骨架法向彻底无关。
否决：骨架法向分侧 原始需求设想"用骨架分割边界、保留法向正侧"。样本图上逐点实测： 
i= 411 p=(420,682) +n→_background_  -n→MgO_L
i= 651 p=(431,443) +n→Block_U       -n→_background_
器件在低处位于法向负侧、高处位于正侧 —— 没有哪个符号能沿整条带选中同一侧，会中途翻面。
画幅切边会伪造出最尖的拐角 Milling 带跑出视场边界，外侧边缘因此包含裁剪产生的直边和两个 90° 拐角 —— 那是整条边上曲率最大的地方。加这条判据之前 m2 就落在图像右边界上。
现在丢弃距画幅边界或旋转填充 4 px 以内的像素。（旋转填充用 255=ignore 正是为此： 校平后切边变成图内一条斜线，唯一还能证明它是"裁剪"的信息，就是它外侧属于原画幅之外。）
04 · 量测 M5 (2/2)

milling_l/r — 定位靠样条，量值靠密切圆

整条边用三次 B 样条平滑后取解析曲率 κ(s)。直段 κ≈0 抢不到最大值，所以不需要真的去拟合"直—弯—直"分段模型。

曲率幅值是尺度相关的，样条值系统性偏小 平滑样条会把节点数削减到残差与 s 匹配，而少数几段三次曲线撑不住恒定曲率。 在真值半径 200 px 的合成弧上：样条报 168 px（−16%），密切圆报 190 px（−5%）。
字段用途说明
radius / kappa_*定位 m1/m2来自样条解析导数，位置可靠，幅值偏小 ~15%
local_circle.radius看幅值在同一点对原始边缘点拟合的圆，精度约 5%
local_circle.rms可信度真实拐弯不是圆弧，1–2 px 正常；>3.5 px 才置 reliable=false 并告警
tail_left/right模型校验两端各 25% 弧长的直线拟合，验证"直—弯—直"；也可当研磨侧壁角
"中间曲线"没有客观定义 实测拐点在弧长的约 73%（不是中点），所以 --milling-middle-frac 默认 1.0（不限制中段）—— 直段本来就抢不到最大值。最大值若落在搜索带边界上会告警。
这段说明原样写进了 JSON magnitude_note 字段直接告诉读数据的人"该用哪个半径"，不依赖有没有人读过文档。
实测 26 张：m1 圆半径中位数 4.835 nm，m2 5.329 nm。
04 · 量测 M6

non_mag — 横向边缘与端点

取哪条边默认 auto：统计上下两条边与 Block_D 接触的列数，取接触少的那条。样本图 top:172 / bottom:0 → 取下边缘。不写死 "bottom"，是为了样品倒装或类别重标时不会悄悄量错界面
边缘提取　逐列取最极端的前景像素。Non_mag 上下缘都是 x 的单值函数，所以这就是边缘，无需分侧启发式
拟合　σ 剔除（默认 2σ）的 TLS。左右两角是圆倒角，不剔会把直线拽歪
端点　把拟合直线向外延伸到区域 x 最小/最大列，而不是停在参与拟合的列上
为什么端点要延伸到区域边界 被 σ 剔除的恰恰是两端圆角掉的列。停在那里，端点就会随剔除阈值内缩； 延伸到区域边界后，端点是区域的属性而不是阈值的属性。y 取直线的值（不取原始像素），所以圆角本身不污染纵坐标。
"最大连通域"不等于"对的那个" 26 张里有一张的预测在画幅底部长出一条 Non_mag 带，面积（11128 px）比真正的方块还大， 按面积选就量到了伪迹上 —— 边缘长度报 33.98 nm，正常值约 10 nm。 现在 Non_mag 的连通域锚定在 Block_D 上：先只在"与 Block_D 相邻"的连通域里挑，挑不到再退回按面积。修复后该图 9.14 nm。
04 · 量测 M7

corner_offsets — Non_mag 端点 ↔ Milling 拐点

量 Non_mag1→m1 与 Non_mag2→m2 的 dx/dy 和直线距离。

特殊之处唯一一个组合其它量测结果的模块。不重算，而是从 ctx.results 里把 M5、M6 的结果读回来
顺序约束因此在注册表里必须排在 non_mag / milling_* 之后
降级任一侧依赖的量测失败时，该侧单独变成 null，另一侧照常输出；两侧都拿不到才整个模块失败
叠加图青绿色点划折线，横竖两段分别对应 dx 和 dy
实测Nm1→m1.dx 中位数 −1.251 nm，Nm2→m2.dx +1.288 nm（左右反号，对称）
这个模块示范了架构的可组合性 新增一个"组合型"量测，不需要重新实现任何几何算法 —— 只要在注册表里排在依赖之后， 用 ctx.measured_point() 把点读回来即可。失败降级也是逐侧的， 所以一张丢了单侧 Milling 的掩膜，另一侧的偏移依然有效。
a = ctx.measured_point("non_mag", "Non_mag1")
b = ctx.measured_point("milling_l",
                       "max_curvature_point")

    ctx.warn(...); return {...: None}

06 · 可靠性

selftest.py 覆盖了什么

全部为合成几何 + 已知真值，不依赖真实数据 —— 所以可以随时跑、跑得快、结论无争议。

  • Guo–Hall：两套实现对直带/折弯带/随机团逐像素一致
  • 旋转：正反变换往返误差 < 1e-9 px；按拟合角旋转后恰好水平
  • 直线：精确直线 TLS 角度误差 < 1e-6°；R² 退化标记按预期触发
  • 圆：精确圆解析曲率半径误差 < 1%（50 / 200 / 600 px）
  • 轮廓：矩形环长度精确，环绕连续段选取正确
  • 端到端（未倾斜）：a1/a2/b1/b2、dx/dy、角度、rmse 误差为 0
  • Non_mag 自动选边：合成图与真实图同构，必须选中下边缘
  • corner_offsets：报出的 dx/dy 必须精确等于所命名两点之差（1e-9 px）
  • 干扰连通域：塞一条比真 Non_mag 大 6 倍（57000 vs 9150 px）且远离 Block_D 的假带，必须仍落在真方块上 —— 复现真实批次里那张坏预测
  • 标尺：端到端跑一张，nm/px 必须精确等于 FOV/宽度
  • Milling 分侧：内外半径已知（200/215 px），outer/inner 各须落在对应半径
  • 倾斜 3° 再校平：恢复倾角误差 < 0.05°，密切圆半径误差 < 10%
自检证明的是"实现符合定义"，不是"定义符合需求" 这是两件事。后者需要一批人工量过的图作为标定集 —— 见倒数第二页。

新增一项量测：写一个文件 + 注册一行

架构就是为"加量测"设计的，不需要改任何已有模块。

def measure(ctx: AnalysisContext) -> Dict[str, Any]:
    # 1. 掩膜：prefer_near 让连通域选择依赖邻接而非面积
    mask = ctx.mask(CLASS, prefer_near=AWAY_FROM)

    # 2. 几何：骨架带缓存
    line = ctx.centerline(CLASS, extend=("xmin","xmax"))
    tls  = fit_line_tls(line.pts)   # 角度用 TLS
    ols  = fit_line_ols(line.pts)   # R²/rmse 用 OLS
    p1, p2 = tls.endpoints_spanning(line.pts)

    # 3. 不确定就 warn，不要静默
    if ols["axis"] != "y~x":
        ctx.warn("...")

    # 4. 距离用 ctx.dist，点用 ctx.point，偏移用 ctx.offset
    return {
        "skeleton_length": ctx.dist(line.length),
        "angle_deg_image": tls.angle_deg_image,
        "rmse": ctx.dist(ols["rmse_px"]),
        "blockD1": ctx.point(p1),
        "blockD2": ctx.point(p2),
        "endpoint_rule": "...",   # 规则写进数据
    }

08 · 局限

已知的方法论局限

这几条不是 bug，是方法本身的边界。写在这里是为了不让人误用数字。

1 · 骨架端点内缩 默认偏内侧约半个带宽，靠端点差分抵消。需要绝对端点时用 --endpoint-extend region。
2 · 校平引入 1–2 px 重采样噪声 自检里残余角 0.007°，但 dy 误差可达约 5 px。对 dy 敏感的指标可考虑 --no-rotate 并自行处理倾斜。
3 · 曲率是尺度相关量 1 px 量化的边缘上没有唯一"真"曲率。当前给两个数（样条 + 密切圆）并说明各自偏差， 但用户必须知道自己在用哪个。
4 · 分割误差没有被量化 —— 整条链路最大的未量化误差源 量测工具假设标签图是对的。分割把边界画偏 2 px，所有下游数字就偏 0.15 nm， 而且没有任何 warning。
目前唯一的缓解手段是 --overlay-on：把标注画在原始 TEM 灰度图上，靠人眼发现分割错位。
