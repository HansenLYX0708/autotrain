TEM 断面：分割 + 几何量测 系统汇报

用语义分割把 TEM 断面拆成 11 个结构层，再在标签图上做亚纳米级几何量测，逐图输出 JSON / 叠加图，批量输出 CSV。
代码：tools/napari_seg + tools/tem_analysis 分析工具版本 v1.0.0 7 个量测模块 73 列汇总 CSV 实测批次 26 张 / 0 失败

00一页速览

这套东西解决的问题是：TEM 断面照片的结构尺寸，以前靠人在图上手动拉线量，慢、不可复现、批次之间没法比。 现在的做法是先用分割模型把每一层"认"出来，再用一套确定性的几何算法在标签图上量，结果全部落成机器可读的字段。

01整体链路

一句话概括：先分割，再分析。分割负责"哪里是什么"，分析负责"它有多大、偏了多少"。 两步之间唯一的接口就是 PaddleSeg 输出的伪彩标签图。

接口约定：只吃 pseudo_color_prediction/ added_prediction/ 是原图与掩膜的混合预览，颜色被灰度污染了，不是标签图。分析工具会主动拒绝： 把 RGB 往调色板上吸附时，如果离色像素超过 5%，直接报错而不是硬算出一堆错数字。

02分割训练逻辑

2.1 标注与数据集（tools/napari_seg/annotate.py）

标注器是基于 napari 的一个薄封装，输出目录直接就是 PaddleSeg 的数据集格式：

<out>/
  JPEGImages/       原图（文件名已做 ASCII 安全化）
  Annotations/      8-bit 调色板 PNG，像素值 == 类别 id
  train.txt         每行 "JPEGImages/xxx.jpg Annotations/xxx.png"
  val.txt
  class_names.txt   第一行永远是 _background_
要点说明
文件名安全化PaddleSeg 按空白字符切分 train.txt 的行，所以 [A-Za-z0-9._-] 之外的字符（中文、空格、括号）一律替换成 _，重名加 _2、_3 后缀。--print-names --no-gui 可以先预览改名结果。
调色板build_palette() = PASCAL VOC colormap 去掉首个黑色项，因此 类别 id == 调色板索引，类别 0 是 (128,0,0) 暗红而不是黑色。这也是分析工具能直接把 RGB 反查回 id 的原因——两边共用同一个函数，不会走偏。
类别顺序即 id本项目 11 类：SAF_Ru_L, SAF_Ru_R, MgO_L, MgO_R, MgO_C, Non_mag, Milling_L, Milling_R, Leveling, Block_U, Block_D，加背景共 12。顺序一旦变了，所有历史标签就全错位，所以固化在 class_names.txt 里随数据集走。
断点续标不带 --classes 再次打开同一个 --out，类别会从 class_names.txt 读回来。

2.2 一个训练任务 = 三份 YAML 深合并

网页端不是让人写一整份 PaddleSeg 配置，而是把配置拆成三份独立维护、启动任务时再合并：

数据集配置 ─┐
训练配置   ─┼─► 深合并 YAML ─► tools/train.py ─► stdout 解析进 TrainingLog 表
模型配置   ─┘

优先级：dataset → training → model（后者覆盖前者，逐 key 合并）
配置负责典型内容
数据集配置数据从哪来train_dataset / val_dataset、dataset_root、num_classes、transforms
训练配置怎么练batch_size、iters、optimizer、lr_scheduler
模型配置练什么model（架构 + backbone）、loss
PaddleSeg 的三个硬约束（踩过的坑）
  • 按 iteration 训练，不是 epoch。iters 才是总步数，warmup_iters、save_interval 同理。数据库里 epoch 那几列对 Seg 项目存的其实是迭代数。
  • len(loss.types) 必须等于模型输出的 logits 数（主头 + 辅助头），否则直接 RuntimeError: The length of logits_list should equal to the types of loss config。 所以 loss: 永远写在模型配置里，绝不写在训练配置里——这样任意训练预设都能和任意模型预设自由组合而不会配错。 UNet=1、OCRNet=2、PP-LiteSeg=3、BiSeNetV2=5。
  • save_dir / save_interval / log_iters 是命令行参数，不是 YAML 键。
为什么必须"深合并"而不是把三段文本拼起来 拼接会产生重复的顶层 key。PyYAML 容忍（后者赢），但文档本身是非法 YAML，用 yaml.parse() 读就抛 Map keys must be unique。而且合并是逐 key 的，训练配置可以只改 train_dataset.transforms 里的一项而不用把整个数据集块重抄一遍。

2.3 训练启动与日志

# 网页端实际生成并执行的命令（PaddleSeg 分支）
python -m paddle.distributed.launch --gpus 0 tools/train.py `
    --config   "<merged>.yml" `
    --do_eval `
    --save_dir "<output>/jobs/<job_name>"

3.3 标尺与校平：所有数字的两个前提

标尺（nm/px）

默认从文件名正则取视场：..._FOV_76.37nm.png → 76.37 nm，再除以图像实际宽度。 样本批次 26 张全部解析成功，得到 76.37 / 1024 = 0.074580 nm/px。

  • 除以实际宽度而不是写死 1024，是为了掩膜万一以别的尺寸导出时仍然正确；宽度≠1024 时会 warning。
  • JSON/CSV 里都记了 fov_nm / image_width_px / scale_nm_per_px / scale_source，事后可复核换算。
  • 解析不到视场且没给 --scale-nm 时直接报错，不会静默用错标尺。

校平（rectification）

Leveling 层拟合成直线得到倾角，整图按这个角度旋转到水平，之后所有量测都在校平后的图上做。 "dy 是向下偏了多少"这句话只有在校平之后才有物理意义。

  • 插值必须是最近邻（order=0）：数组里装的是类别 id，任何平均都会凭空造出没预测过的类。
  • 填充值用 255(ignore) 而不是 0(背景)，这样"画幅之外"和"预测为背景"仍然可区分——M5 排除切边就靠这个信息。
  • 每个点在 JSON 里同时给校平后坐标和原图坐标（x_px/y_px 与 x_orig_px/y_orig_px），可以直接叠回原始 TEM 图。
  • 代价：旋转带来重采样噪声，层骨架会毛糙 1–2 px。自检里校平后残余角 0.007°，但 dy 误差可达约 5 px。--no-rotate 可完全避开。

04逐项量测说明

7 个模块按注册表顺序执行，后面的可以读前面的结果： leveling → mgo_c → interfaces → milling_l → milling_r → non_mag → corner_offsets。 下面每一项都按 量什么 / 怎么定义 / 算法 / 输出字段 / 坑 说明。

M1 · leveling — 整图校平基准

量什么：样品在图像里的倾斜角，以及 Leveling 层本身有多平。它是唯一一个"结果会反过来影响其它所有量测"的模块。

定义Leveling 类 → 最大连通域 → Guo–Hall 骨架 → 直线拟合 → 倾角
算法角度用 TLS（总体最小二乘）——OLS 在残差与 x 跨度可比时会系统性压平斜率，TLS 对方向无偏；R²/rmse 用 OLS y~x，因为"fit R²"通常就是这个意思。两者都输出，差异摆在明面上。
可靠性用 angle_stderr_deg（斜率标准误 = σ/√Σ(x−x̄)²）判断，不要用 R²。校平后会重新拟合一次，残余角 > 0.05° 就告警——这是对整条旋转/逆变换链路的免费自检。
输出angle_deg_image、angle_deg_math、angle_stderr_deg、rmse、max_residual、skeleton_length、residual_angle_deg_after_rotation、rectified{...}
R² 对近水平的层没有意义 R² = 1 − SS_res/SS_tot，而水平层的 SS_tot（y 的方差）本身极小，所以一条 1029 px 长、rmse 只有 1.9 px 的优秀直线也只能得到 R² ≈ 0.02。 Leveling / MgO_C / Non_mag 都是这种情况。结果里带 fit_r2_degenerate: true 标记和 fit_r2_note 说明。 判断平直度请看 rmse 和 max_residual。

M2 · mgo_c — MgO_C 层的平直度与倾角

量什么：中间那条 MgO 势垒层拟合成直线后的角度、拟合优度，以及这条拟合线段的两个端点 b3/b4。

定义MgO_C 骨架 → TLS 直线；b3/b4 = 把骨架 x 最小/最大的两个极值点投影到拟合直线上得到的线段端点
为什么要 b3/b4b1/b2（M3）是骨架的真实端点，b3/b4 是直线模型上的端点。两者之差就是该处层的局部起伏。所以 a1→b1 和 a1→b3 同时给：前者对准真实端点，后者对准模型、对局部毛刺不敏感。实测两者 dx 几乎一致（中位数 5.332 / 5.333 nm），但 b3 的 dy 离散度更小。
输出angle_deg_image/math、fit_r2(+degenerate 标记)、fit_slope/intercept、rmse、max_residual、perp_rmse（垂直距离 rmse）、b3、b4、fit_length、residual_profile（逐点残差曲线）
实测rmse ≈ 0.045 nm（0.6 px），max_residual ≈ 0.126 nm。倾角在批次内 −3.5°～+3.5° 之间波动。

M3 · interfaces — 层间端点偏差 a↔b

量什么：左右两侧 SAF_Ru 层的内端点，相对 MgO_C 层端点的横纵偏移。这是这套系统最核心的一组数。

端点定义 a1 = SAF_Ru_L 骨架 x 最大端（朝向器件那头）
a2 = SAF_Ru_R 骨架 x 最小端
b1/b2 = MgO_C 骨架的 x 最小/最大端
b3/b4 = MgO_C 拟合线段的两个端点（来自 M2）
输出的四组偏移a1_b1、a1_b3、a2_b2、a2_b4，每组含 dx/dy/distance，各自都有 px 和 nm
符号约定dx>0：b 在 a 的右侧；dy>0：b 在图像中比 a 更低。这句话原样写在每个 offset 的 convention 字段里，避免看报表的人猜。
实测26 张：a1_b1.dx 中位数 +5.332 nm（σ 0.61），a2_b2.dx 中位数 −5.332 nm（σ 0.50）——左右对称，符合物理预期。
骨架端点会内缩 Guo–Hall（任何形态学细化都一样）会从区域尖端回缩约半个带宽，所以 a1/b1 默认偏内侧；合成算例里 13 px 厚的层正好内缩 6 px。 --endpoint-extend region 可沿端点切线外推回区域尖端补偿（自检里该模式下 a1 误差为 0），默认关闭以保持"忠实于 Guo–Hall"。 好消息是 dx/dy 是两个端点之差，两侧内缩量相近时会大部分抵消。

M4 · *_dip — 端点 5 nm 内的最大下沉量

量什么：从 a1（或 a2）沿 SAF_Ru 骨架往回走 5 nm，这段里层最多往下掉了多少。表征端点附近的塌陷/弯曲。

基准端点自身：dev = y − y(端点)，正值 = 更低
窗口沿弧长回走 5 nm，不是沿 x。端点附近层是弯的，按 x 取窗口会覆盖到不同长度的实际层。
输出window(请求值/实际 px+nm)、window_points、window_start/end、window_polyline（被搜索的骨架段原样输出）、max_downward_deviation、max_downward_point、max_downward_arclength（在窗口内多远处取到的）、max_abs_deviation/max_abs_point（绝对值最大，可能是向上）、deviation_profile（整条 s–dev 曲线）
叠加图画法洋红色：加粗骨架段 = 被搜索范围，两端竖线 = 窗口边界，虚线 = 端点基准线，箭头指向最大偏差点并标数值。
实测左侧中位数 0.597 nm（0～1.417），右侧 0.709 nm（0.224～1.268）。
为什么把整条 deviation_profile 也写进 JSON 这样想换个窗口长度、或者想看"最大值是不是一个孤立毛刺"，不必重跑整批，直接在 JSON 上复核。M5 的 curvature_profile、M2 的 residual_profile 同理。

M5 · milling_l / milling_r — 研磨面曲率与 m1/m2

量什么：离子研磨加工出来的那个侧面，它的形状是"直—弯—直"，要找到弯得最厉害的那个点（m1 左 / m2 右）以及那里的曲率半径。

(a) 取哪一侧：邻接判据，不是骨架法向

一条 Milling 带有两个侧面，一侧贴器件（MgO_L/MgO_R/Block_*），一侧朝真空。默认 outer = 朝真空那侧， 做法是保留"不与任何其它类相邻"的边界像素，再取轮廓顺序上最长的连续段。

为什么放弃了"骨架法向分侧" 原始需求设想用骨架把边界一分为二、保留法向正侧。在样本图上逐点实测两侧的邻居类别： 
i= 411 p=(420,682)  +n -> _background_   -n -> MgO_L
i= 651 p=(431,443)  +n -> Block_U        -n -> _background_
器件在低处位于法向负侧、在高处位于法向正侧——没有哪个符号能沿整条带选中同一侧，会中途翻面。 改用邻接判据后与骨架法向彻底无关。--milling-edge-method skeleton 保留原方法仅供对比。

(b) 排除画幅切边

画幅切边会伪造出最尖的拐角 Milling 带跑出视场左右边界，外侧边缘于是包含一段由裁剪产生的直边和两个 90° 拐角——那是整条边上曲率最大的地方。 加这条判据之前 m2 就落在图像右边界上。现在会丢弃距画幅边界或旋转填充 4 px 以内的边界像素。 （旋转填充用 255=ignore 而不是背景，正是为了这个：校平后那条切边变成图像内部的一条斜线，唯一还能证明它是"裁剪"而非真实表面的信息，就是它外侧属于原画幅之外。）

(c) 定位靠样条，量值靠密切圆

整条边用三次 B 样条平滑后取解析曲率 κ(s)，直段 κ≈0 抢不到最大值，所以不需要真的去拟合"直—弯—直"分段模型。

曲率幅值是尺度相关的，样条值偏小 splprep 会把节点数削减到残差与 s 匹配，而少数几段三次曲线撑不住恒定曲率：在真值半径 200 px 的合成弧上， 样条报 168 px（−16%），密切圆拟合报 190 px（−5%）。所以：
  • radius / kappa_* 来自样条解析导数，定位 m1/m2 可靠
  • local_circle.radius 是在同一点对原始边缘点拟合的圆，看幅值请用它
  • local_circle.rms 是拟合残差；真实拐弯不是圆弧，1–2 px 属正常，超过 3.5 px 才把 reliable 置 false 并告警
这段说明原样写在 JSON 的 magnitude_note 字段里。
输出edge_method、boundary_points/selected_points/edge_points、edge_length、spline_rmse、search_band_nm、max_curvature_point(=m1/m2)、max_curvature_arclength、kappa_per_px/kappa_per_nm/kappa_abs_per_nm、radius、local_circle{centre,radius,rms,points,window,reliable}、tail_left/tail_right（两端各 25% 弧长的直线拟合，用于校验"直—弯—直"）、edge_polyline、curvature_profile
符号kappa>0 表示在图像坐标（y 向下）里顺时针转弯
实测26 张：milling_l.local_circle.radius 中位数 4.835 nm，milling_r 5.329 nm。
"中间曲线"没有客观定义 实测拐点在弧长的约 73%（不是中点），所以 --milling-middle-frac 默认 1.0（不限制中段）。若最大值恰好落在搜索带边界上会告警。

M6 · non_mag — Non_mag 横向边缘与 Non_mag1/2

量什么：Non_mag 方块背离 Block_D 那一侧的横向边缘，拟合成直线，给出角度、长度和两个端点。

取哪条边默认 auto：分别统计上下两条边与 Block_D 接触的列数，取接触少的那条。样本图上 top:172 / bottom:0，于是取下边缘。这样写而不是写死 "bottom"，是为了样品倒装或类别重标时不会悄悄量错界面。edge_side 与两个接触计数都写进 JSON/CSV。
边缘提取逐列取该列最极端的前景像素。Non_mag 的上下缘都是 x 的单值函数，所以这就是边缘，不需要任何分侧启发式。
拟合σ 剔除（默认 2σ）的 TLS。左右两个角是圆倒角，不剔会把直线拽歪；一个孤立的错误预测像素也会主导普通最小二乘。
端点定义把拟合直线向外延伸到 Non_mag 区域的 x 最小/最大列，而不是停在参与拟合的列上。被剔除的恰恰是两端圆角掉的列，停在那里会让端点随剔除阈值内缩；延伸到区域边界后，端点是区域的属性而不是阈值的属性。y 取直线的值（不取原始像素），所以圆角本身不污染纵坐标。max_extrapolation 记录延伸了多少。
输出edge_side、edge_side_rule、block_d_contact_columns{top,bottom}、edge_columns/columns_used/columns_dropped、Non_mag1、Non_mag2、endpoint_rule、region_x_range_px、max_extrapolation、angle_deg_image/math、length、fit_r2、rmse、max_residual、edge_polyline
"最大连通域"不等于"对的那个" 26 张里有一张的预测在画幅底部长出一条 Non_mag 带，面积（11128 px）比真正的 Non_mag 方块还大，按面积选就量到了那条伪迹上——边缘长度报 33.98 nm 而正常值约 10 nm。 现在 Non_mag 的连通域锚定在 Block_D 上：先只在"与 Block_D 相邻"的连通域里挑，挑不到再退回按面积。修复后该图为 9.14 nm，回到正常区间。 其余类别仍按面积选；任何丢弃都会写 warning 并注明是否用了锚定。

M7 · corner_offsets — Non_mag 端点 ↔ Milling 拐点

量什么：Non_mag1 → m1 和 Non_mag2 → m2 的 dx/dy 和直线距离。描述"方块的角"和"研磨面拐弯处"错开了多少。

特殊之处这是唯一一个组合其它量测结果的模块。它不重算，而是从 ctx.results 里把 M5、M6 的结果读回来——所以在注册表里必须排在 non_mag / milling_* 之后。
降级任一侧依赖的量测失败时，该侧单独变成 null，另一侧照常输出。两侧都拿不到才整个模块失败。
输出non_mag1_m1 / non_mag2_m2，各含 from/to（点名）、from_point/to_point（双坐标）、dx/dy/distance、convention
叠加图青绿色点划折线，横竖两段分别对应 dx 和 dy，中间标注数值
实测26 张：non_mag1_m1.dx 中位数 −1.251 nm，non_mag2_m2.dx +1.288 nm。

量测可信度：selftest.py 覆盖了什么

全部用合成几何 + 已知真值，不依赖真实数据，所以可以随时跑、跑得快、结论无争议。

展开自检项清单
  • Guo–Hall：OpenCV 与 NumPy 两条实现对直带 / 折弯带 / 随机团逐像素一致
  • 旋转正反变换往返误差 < 1e-9 px；按拟合角旋转后方向恰好水平
  • 精确直线的 TLS 角度误差 < 1e-6°；R² 退化标记按预期触发
  • 精确圆的解析曲率半径误差 < 1%（50 / 200 / 600 px 三个尺度）
  • 轮廓追踪：矩形环长度精确，环绕连续段选取正确
  • 未倾斜整图端到端：a1/a2/b1/b2、dx/dy、角度、rmse 误差为 0；骨架内缩量落在预期区间（13 px 厚的层正好缩 6 px）
  • Non_mag 自动选边：合成图与真实图同构（Block_D 紧贴 Non_mag 上方），必须选中下边缘
  • corner_offsets：报出的 dx/dy 必须精确等于它所命名的两点之差（1e-9 px），nm 换算同样精确
  • 干扰连通域：塞一条比真 Non_mag 大 6 倍（57000 vs 9150 px）且远离 Block_D 的假带，量测必须仍落在真方块上（复现真实批次里那张坏预测）
  • 标尺：文件名解析（含无视场时返回 None）；端到端跑一张 ..._FOV_76.37nm.png，nm/px 必须精确等于 76.37/宽度
  • b3/b4：合成图的 MgO_C 是完美矩形，拟合端点必须与骨架端点重合
  • Milling 分侧：合成图内外两侧半径已知（200 / 215 px），outer 与 inner 各须落在对应半径上；选中的边缘不得包含画幅边界像素
  • 倾斜 3° 再校平：恢复倾角误差 < 0.05°，残余角 < 0.05°，密切圆半径误差 < 10%

可以直接抄的骨架

"""Requirement N: <一句话说清量什么>.

<为什么这么定义。如果有被否掉的替代方案，写清楚为什么否掉——
 半年后的人（包括你自己）一定会想"为什么不用更简单的 XXX"。>
"""

from __future__ import annotations

from typing import Any, Dict

import numpy as np

from context import AnalysisContext, MissingClass
from geometry import fit_line_ols, fit_line_tls

CLASS = "Block_D"          # 主类
AWAY_FROM = "Non_mag"      # 用于消歧的邻居类（如果需要）


def measure(ctx: AnalysisContext) -> Dict[str, Any]:
    # --- 1. 拿掩膜。prefer_near 让"选哪个连通域"依赖邻接而不是面积 ---
    mask = ctx.mask(CLASS, prefer_near=AWAY_FROM)     # 缺类会抛 MissingClass

    # --- 2. 拿几何。骨架带缓存；extend 只在 --endpoint-extend region 时生效 ---
    line = ctx.centerline(CLASS, extend=("xmin", "xmax"))
    tls = fit_line_tls(line.pts)      # 角度用 TLS（方向无偏）
    ols = fit_line_ols(line.pts)      # R²/rmse 用 OLS
    p1, p2 = tls.endpoints_spanning(line.pts)

    # --- 3. 不确定就 warn，不要静默 ---
    if ols["axis"] != "y~x":
        ctx.warn("{}: closer to vertical; R2 computed on x~y".format(CLASS))

    # --- 4. 返回。距离用 ctx.dist()，点用 ctx.point()，偏移用 ctx.offset() ---
    return {
        "skeleton_points": int(len(line)),
        "skeleton_length": ctx.dist(line.length),        # -> {px, nm}
        "angle_deg_image": tls.angle_deg_image,
        "angle_deg_math": tls.angle_deg_math,
        "fit_r2": ols["r2"],
        "fit_r2_degenerate": ols["r2_degenerate"],       # 近水平时为 True
        "fit_r2_note": ols["r2_note"],
        "rmse": ctx.dist(ols["rmse_px"]),
        "max_residual": ctx.dist(ols["max_residual_px"]),
        "blockD1": ctx.point(p1),                        # -> {x_px,y_px,x_orig_px,y_orig_px}
        "blockD2": ctx.point(p2),
        "endpoint_rule": "the fitted line extended to the x extent of the region",
        "residual_profile": [                            # 曲线序列，便于事后复核
            [ctx.nm(float(s)), ctx.nm(float(r))]
            for s, r in zip(line.s, tls.signed_distance(line.pts))
        ],
    }


# 如果要组合别的量测结果（像 corner_offsets 那样）：
def measure_combined(ctx: AnalysisContext) -> Dict[str, Any]:
    a = ctx.measured_point("non_mag", "Non_mag1")        # 拿不到就返回 None
    b = ctx.measured_point("milling_l", "max_curvature_point")
    if a is None or b is None:
        ctx.warn("...: 依赖的点不可用")
        return {"offset": None}
    return {"offset": {"from_point": ctx.point(a), "to_point": ctx.point(b),
                       **ctx.offset(a, b)}}

ctx 提供的全部工具

调用作用
ctx.mask(name, prefer_near=None)清理过的布尔掩膜（已按 min_area 过滤 + 只留最大/锚定连通域），带缓存，丢弃会自动 warn
ctx.centerline(name, extend=())Guo–Hall 骨架的最长路径 Polyline，带缓存
ctx.centroid(name)类质心
ctx.nm(px) / ctx.px(nm)单位换算
ctx.dist(px)→ {"px":…, "nm":…}
ctx.point(xy)→ 校平坐标 + 原图坐标
ctx.offset(a, b)→ dx/dy/distance + convention 说明
ctx.measured_point(key, *path)读回前面模块算出的点，不可用时返回 None
ctx.polyline_out(line, step)折线序列化
ctx.warn(msg)写一条去重的 warning
ctx.params / ctx.classes / ctx.ids / ctx.rect / ctx.scale_nm参数、类别表、校平后的 id 数组、变换器、标尺

Polyline（skeleton.py）另有：.length、.s(弧长)、.pts、.x/.y、 .endpoint("xmin"|"xmax"|"ymin"|"ymax")、.window_from(end, max_s)、.tangent(i)、.tangents()。 geometry.py 另有：fit_line_tls/ols、trimmed_line_fit(σ剔除)、fit_circle、Spline.fit/curvature/sample。 contour.py：trace_outer_contour(有序外轮廓)、longest_run(环形最长连续段)。

写新量测时请遵守的约定

五条
  1. 缺类抛 MissingClass，不要 return None。框架会把它转成 null + warning 并继续跑批。
  2. 任何长度都走 ctx.dist()，任何点都走 ctx.point()。不要自己乘标尺，不要只给一种坐标。
  3. 魔数变成 CLI 参数。这样它会自动出现在 JSON 的 params 里，结果永远可追溯。
  4. 把"规则"写进输出。像 endpoint_rule、convention、magnitude_note 这样，让数据自解释。
  5. 先写自检再写实现。合成一个已知真值的几何，让新量测在上面误差为 0；真实数据上"看起来对"不算数。

8.1 已知缺失的量测能力

能力现状补起来的成本
Block_D 下边缘（blockD1 / blockD2）readme 和 report.py 的注释里还留着痕迹，但当前 MEASURES 里没有这一项，CSV 里也没有对应列。早期需求 7 后来被 corner_offsets 取代了。小。完全套用 non_mag.py，见 §7 示例
逐类形状统计（每类的面积 px/nm²、轮廓周长、骨架长度）无。当前只有个别模块顺带输出了自己那条骨架的长度。小。一个遍历 ctx.classes 的模块即可，但 CSV 会膨胀到 ~100 列（11 类 × 8 项）
MgO_L / MgO_R / Block_U 的量测这三类被标注了、也被分割了，但没有任何量测用到它们（只在 Milling 分侧时作为"邻居"参与判断）。取决于需求定义
层厚度（每层垂直方向的厚度及其沿 x 的分布）无。目前所有量测都是端点/边缘/角度，没有"厚度"。中。需要定义"沿哪个法向测"，以及处理层弯曲

结果回写数据库 / 网页展示分析工具是完全独立的 CLI，与 Next.js 平台之间没有任何代码耦合，结果也不进数据库。中。需要设计表结构 + 一个触发分析的 API 路由
与人工量测的对比验证自检验证的是"算法实现是否符合定义"，没有验证"定义是否符合客户想要的"。需要一批人工量过的图作为标定集
一个需要澄清的现象 在 G:\datasets\TEM\1300kgroup2\normal_test_temfull\ 下存在一批更晚（8/10）产出的结果，其 CSV 有 559 列， 包含 class_shapes.*（逐类面积/周长/骨架长）、block_d_left.*、block_d_right.* 等本仓库不存在的字段， 命名风格也不同（PascalCase vs 现在的点分小写）。 说明曾经存在（或正在别处存在）一个功能更全的变体，但它不在本仓库里。 上表中的"缺失"是相对当前仓库代码而言的 —— 如果那份变体还找得到，很多项可以直接移植而不用重写。

8.2 已知的方法论局限

  • 骨架端点内缩：默认偏内侧约半个带宽，靠差分抵消。需要绝对端点时用 --endpoint-extend region。
  • 校平引入 1–2 px 重采样噪声：自检里残余角 0.007°，但 dy 误差可达约 5 px。对 dy 敏感的指标可考虑 --no-rotate 并自行处理倾斜。
  • 曲率是尺度相关量：1 px 量化的边缘上没有唯一"真"曲率。当前给两个数（样条 + 密切圆）并说明各自偏差，但用户必须知道自己在用哪个。
  • 分割误差没有被量化：分析工具假设标签图是对的。分割把边界画偏 2 px，所有下游数字就偏 0.15 nm，而且没有任何 warning。这是整条链路里最大的未量化误差源。
